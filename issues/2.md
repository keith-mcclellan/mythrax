---
title: Bug: Unbounded recursion / DoS risk in temporal expansion graph traversals
labels: [bug,agent-found]
---

**Severity:** High

**File:** `mythrax-core/src/db/crud_operations.rs`
**Line:** 2570

**Description:**
In `expand_symbolic_context`, a breadth-first search is performed using a `VecDeque`. However, for each node popped from the queue, a query with `LIMIT 50` is executed to fetch its neighbors. At depth `d`, the number of nodes explored can grow by 50^d. A depth of 3 could evaluate 50^3 = 125,000 edges, potentially causing denial of service due to excessive memory usage and database load, as adversarial memory graphs can be densely connected.

**Minimal Reproducible Scenario:**
Create a densely connected graph of memory nodes (e.g. 50 out-edges per node up to depth 3). Trigger `expand_symbolic_context` with `max_depth = 3`. The traversal will execute thousands of queries and exhaust memory.

**Suggested Fix:**
Limit the size of the `VecDeque` explicitly (e.g., sliding window cap, max queue size of 1000), or strictly limit the total number of edges evaluated globally rather than per-hop, to bound execution memory.
