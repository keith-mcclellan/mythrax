## 2024-05-18 - [NoSQL Injection via String Interpolation in get_node_scope]
**Vulnerability:** In `mythrax-core/src/mcp_routes/manage_handlers.rs`, the `get_node_scope` function was vulnerable to NoSQL Injection. It constructed a query string using `format!("SELECT scope FROM {};", rec_id.table);` where `rec_id.table` came directly from user input via the `parse_record_id` function, which blindly parsed standard string representations of record IDs (e.g. splitting by `:`). If an attacker passed a maliciously crafted record ID string, they could specify arbitrary table names or potentially inject subqueries/operators if not fully validated by SurrealDB's parser.
**Learning:** Even when the value appears to be parsed by an internal function (`parse_record_id`), if the internal function just splits a string on a delimiter like `:` and returns the left side without validation, passing that left side into a query string via interpolation creates a NoSQL injection vulnerability. SurrealDB queries should use placeholders even for generic selects (e.g., `SELECT scope FROM $id`) or parameterize tables with `type::table($table)`.
**Prevention:** Always use parameterized queries for all database inputs, including table and record IDs. In SurrealDB, one can use `$id` directly when querying a specific record, e.g. `SELECT field FROM $id`, avoiding the need to manually interpolate the table and use `WHERE id = $id`.
