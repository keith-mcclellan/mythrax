## Bug Report: Potential NaN in BM25 IDF calculation

**File:** `mythrax-core/src/retrieval/bm25.rs`
**Line:** 122

**Minimal Reproducible Scenario:**
The Okapi BM25 scoring function calculates IDF using the formula `(((self.n as f32 - df_t as f32 + 0.5) / (df_t as f32 + 0.5)) + 1.0).ln()`. If global IDF stats edge cases cause `df_t` (document frequency in global stats) to exceed `self.n` (the number of documents in global stats), the term inside the logarithm can become zero or negative, resulting in a NaN score. This causes silent logic errors down the line during document ranking and retrieval.

**Severity:** Medium (Correctness/Ranking Degradation)

**Suggested Fix:**
Ensure the argument to the logarithm is strictly positive, perhaps by taking the maximum of a small epsilon and the inner value before applying `.ln()`. Alternatively, bound `df_t` to be at most `self.n`.
