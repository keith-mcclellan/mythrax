---
title: Bug: Integer overflow panic risk in `access_count` metric updates
labels: [bug,agent-found]
---

**Severity:** Medium

**File:** `mythrax-core/src/db/crud_operations.rs`
**Line:** 2919

**Description:**
The `access_count` field on `metrics` records is incremented directly via `let new_count = row.access_count + 1;` without overflow checks (and similarly in raw SQL updates like `access_count = access_count + 1`). If `access_count` (which is an `i64`) overflows, this will cause a runtime panic in Rust or a wrap-around behavior that will severely distort memory `utility_score` calculations.

**Minimal Reproducible Scenario:**
If a system is long-running and repeatedly accesses the same memory node, `access_count` could eventually exceed the maximum value for `i64`.

**Suggested Fix:**
Use `.saturating_add(1)` when incrementing `access_count` in Rust, and implement similar capping logic in SurrealQL queries.
